# Substantive case workflows

Select the case from observed facts and the user's requested remedy. A useful case
can request missing records; it does not require a fabricated quantified demand.

## Competing interests or adverse matching

Capture exact provider record, competing claim/response, represented party, right,
territory and period. Index relevant executed agreements, amendments, split records,
mandates, identifiers and prior submissions. Preserve conflicts and contrary evidence.

Request the provider's actual review/correction/dispute process and the supported
remedy. Do not reduce another claimant's share, create duplicate works or pretend the
agent can adjudicate title. A new supported ordinary claim without an adverse state
belongs to registration. A first recording-work match belongs there too.

For an adverse match, compare the actual recording/work/writer evidence and provider
history. A same-title coincidence is not enough. Keep original, superseding and
rematched records so later royalty accounting can identify the affected period.

## Held royalties or missing accounting

Establish the current hold/absence from a recent statement, ledger, case response or
other support. Separate an old hold from an unknown current balance. Specify payee,
account/right, periods and the provider's stated reason, if any.

If entitlement or current amount is unknown, request the relevant statement, ledger,
hold reason, release requirements or payment reference. Do not substitute historical
credits, public estimates or an empty dashboard for the current payable amount.
Missing authentic consent/signature must come from the authorized person; never
manufacture it or infer it from a login.

When financial workpapers are available, attach the narrow calculation and controls,
not an unrelated full banking export. Distinguish provider acceptance of a correction,
posting to a ledger, remittance issuance and bank-posted cash.

## Denied correction or disputed payment

Identify the denied request, exact reason, prior payload/evidence and current requested
remedy. A required-field error stays with the original registration/delivery workflow;
a substantive refusal can justify this case.

For money, identify the agreement-supported base, period, source rows, computed amount,
reported amount, known adjustments/offsets and unresolved terms. A suspected shortfall
with incomplete basis remains a request for accounting or explanation. Keep provider
counter-calculations and partial agreement separate from the original requested amount.

The provider-specific route must match the object: work/interest correction, hold
release inquiry, accounting dispute and payment trace are different operations.
Do not translate a royalty dispute into a copyright removal notice or legal settlement.

## Prepare and send a bounded communication

Use `templates/correspondence.md`. The packet needs:

1. The represented party and relationship to the exact object/account.
2. The observed problem and dates, stated factually with evidence references.
3. The requested record, explanation or correction and its supported scope.
4. A short list of attachments, necessary disclosed data and known onward recipients.
5. The requested response and any evidenced provider deadline or case reference.

Use existing user authority for the same recipient, attachments and requested remedy.
If authority is absent or a material scope changed, finish this concrete packet before
requesting the missing approval. Do not send speculative attachments "just in case".
Do not make concessions, waive rights, sign, settle or certify facts on the user's behalf
unless those distinct steps have been explicitly authorized and are supported.

## Response handling

| Response/event | Record | Next useful step |
|---|---|---|
| User says message sent | User-reported event with time/recipient if supplied | Await or inspect the existing case; do not resend |
| Inspected sent record | Exact sent version, receipt/message ID, attachments | Track response against that version |
| Acknowledgment | Provider case ID and response date | Keep substantive issue open |
| Request for evidence | Specific missing items and reason | Gather authentic support; retain unresolved items |
| Partial response | Items answered, items omitted, any new evidence | Draft a bounded follow-up for remaining scope |
| Accepted correction | Granted change, effective date and provider evidence | Read back actual record; preserve residual money questions |
| Adjustment offered/posted | Proposed versus accepted/posted amount and currency | Reconcile ledger effect before claiming entitlement/cash |
| Denial | Reason, evidence relied upon and available appeal route | Produce an evidenced escalation option; do not repeat the same filing |
| Payment marked sent | Provider reference/date/amount | Trace actual remittance and relevant bank receipt |

An uncertain network/send outcome first requires inspecting existing receipts,
messages or cases. Repeating the action without checking can create duplicate cases
or conflicting requests. Maintain an append-only event history, including no-action
decisions and source changes.

## Closure and residual issues

Use `templates/disposition.md` with separate fields for rights record, accounting
adjustment, payment and case administration. A provider may close its ticket before
the underlying issue is resolved. Record that fact without treating it as success.

Close only the supported outcome: granted correction observed; accounting response
reconciled; adjustment accepted/posted; cash matched. Leave disputed amounts,
historic periods, rights gaps or future follow-ups as explicit residual items.
Attach current source versions, disposition rationale and next owner so another
authorized session can continue. Scheduled follow-up is an optional user-requested
operation using existing scheduling, never an implicit promise to monitor forever.
