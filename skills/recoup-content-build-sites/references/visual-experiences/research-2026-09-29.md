# Research: visual craft and Opus 5.5

Reviewed September 29, 2026. This is a source-based design study, not a controlled model benchmark. Creator descriptions of one-shot builds remain creator claims. The reference library distinguishes shared prompts, partial briefs and reconstructed catalog prompts. Do not equate social reach with quality.

## Findings to apply

| Source | Documented mechanism | Application to Sites |
| --- | --- | --- |
| [Anthropic Opus 5.5](https://www.anthropic.com/claude-opus-5-5) | Reports improved game graphics/polish in an early tester evaluation; no guarantee for our pipeline | Test the model on our real input and runtime, preserve model provenance |
| [Vercel model API](https://vercel.com/ai-gateway/models/claude-opus-5.5) | Existing gateway supports this model and provider reasoning options | Try high adaptive effort without changing the customer flow |
| [Turbo Kart Rally](https://github.com/bridge-mind/turbo-kart-rally) | Creator documents separated world, driving, effects, art/camera and game/UI responsibilities, with shared contracts | Define controls, visual state and payoff together; spend implementation detail on feel, not only menus |
| [Musical cartoon](https://github.com/az9713/opus-5.5-musical-cartoon) | Storyboard, p5 drawing, code-generated score, exact rendering and sampled-frame inspection | Art needs explicit poses, materials and timing; a film workflow is not automatically a live game |
| [Window Seat](https://github.com/sevenevesai/riso-windowseat) | Procedural print aesthetics, craft documents, deterministic film workflows and recorded weaknesses | Stable texture and a limited material vocabulary can be richer than generic gradients |
| [Clearwater](https://github.com/Aureliengmz/clearwater) | Native WebGL2 water rendering in a standalone document | Browser-native rendering can create rich responsive surfaces without arbitrary network dependencies |
| [Drone fly-through](https://github.com/Barty-Bart/opus-55-10k-websites) | Generated image/video assets, chained camera route, frame extraction, distinct mobile treatment | The striking asset is produced before the page; do not pretend a prompt alone supplies it |
| [Motion graphics skills](https://github.com/charlie947/motion-graphics-skills) | Specialized brand/motion workflows and exports | Load guidance for the chosen medium rather than every design chapter |
| [Opus JS Animations](https://github.com/klsoen/opus-js-animations) | Audio/treatment/timeline/render workflow | Specify attention over time and inspect the defining event, not just the opening frame |
| [Claude Animation](https://github.com/buildwithhanif/claude-animation-skill) | Character rigs, material detail and frame comparison | Consistent pivots, silhouettes and contact precede expressive character animation |
| [Emil Kowalski](https://emilkowal.ski/ui/good-vs-great-animations) | Origin-aware, deliberate animation details | Feedback should emerge from the object acted upon |
| [Carbon motion](https://carbondesignsystem.com/elements/motion/overview/) | Distinguishes productive and expressive motion | Keep repeated controls quick; put expressive motion into the fan's payoff |
| [web.dev animation performance](https://web.dev/articles/animations-guide) | Rendering cost, transform/opacity and profiling guidance | Bound effects and measure actual execution; a screenshot is not a frame-rate measurement |
| [Higgsfield API](https://docs.higgsfield.ai/docs) | Asynchronous model submission and result persistence | Use server-side generation, save finished outputs, expose only asset URLs to the fan site |

## Breadth without a template factory

Use different motivations and media: tactile toys, kinetic typography, illustrated stories, spatial discoveries, expressive drawing instruments and arcade challenges. Choose based on the song's supplied evidence and fan desire. Do not rotate styles mechanically or make every release a quiz, score chase, particle field or cinematic introduction.

Each direction should state a simple fan action, immediate visible consequence, distinctive material/composition, a defining motion moment and a satisfying finish. Richness belongs in the response, not in a long setup form. A one-shot customer experience can contain bounded internal planning, generation and repair; it should not require the customer to art-direct every agent turn.

## Evaluation boundaries

Use the same saved context for a model comparison before changing the song. Then try different release contexts to expose repetition. Record actual model/effort, loaded reference IDs, generated assets, visible strengths and remaining defects. Exercise the normal user-started route. Do not manually patch a generated site and attribute the result to the engine. Successful interaction checks and a strong screenshot are evidence of specific properties, not proof of awards or universal quality.
