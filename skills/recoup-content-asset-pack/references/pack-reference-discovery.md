# Gather references before asking again

Use this procedure before the first creative-context question. Its result is a
small, private collection the creative director can actually inspect and use.
Keep the original song, occasion, budget and chosen working mode in view.

## 1. Reuse Recoup when already connected

Discover the current roster/profile and Context read tools; use their real schemas.
Resolve only the named artist in the selected authorized workspace. Current artist
rows can include `account_id`, name, image, instruction, knowledges and social
links. Inspect the matching row before asking for branding or handles again.
These are saved inputs, not proof that every linked file or profile was read.

Read relevant knowledge links and a selected saved creative brief when available.
Context brief reads require an actual brief ID; compiling one requires actual saved
request IDs. Do not invent an account-wide brief-search tool, recollect a catalog,
or run a paid research module just because the connection exists. Inspect available
coverage; metadata is not listening and an empty roster is valid.

If disconnected, continue with available inputs. Do not interrupt intake to create
an artist or require sign-in merely to develop a visual direction. Connect when
the selected Recoup operation needs authentication, then resume this collection.

## 2. Inspect the customer's selected material

Read attachments, the selected folder, artwork, release notes, past posts, press
photos and screenshots through the host's actual file/browser/connector tools.
Resolve a supplied folder before browsing inside it; do not search the entire
computer or assume a local artist repository exists. In a browser-only host,
use accessible attachments and links without requiring a local folder.

Inspect image pixels before describing their visual style. A filename, profile
URL or search thumbnail does not establish artist identity or the artwork's look.
Keep the release's visual world separate from historical artist branding. Current
explicit customer choices govern this campaign; conflicting older material is
background, not an instruction to replace the chosen world.

If context is still thin, ask one useful question:

> Got artwork, photos or a look to build on? Send them over or point me to them —
> or I can come up with a direction.

Skip that question if the material is already supplied or creative decisions are
already delegated. Keep any remaining identity/audio/budget gaps together in a
short reply; do not turn this into a profile interview.

## 3. Fill actual gaps from accessible sources

Use an official artist page, linked press kit or correctly matched profile first.
Confirm namesakes using the supplied recording, verified handles or selected
Recoup identity. A shared display name alone is insufficient. If the match changes
which person or recording would appear, ask one focused identity question.

Look for useful artist photos, existing artwork and visual treatments rather than
collecting an exhaustive biography. Begin with one pass through available Recoup
and customer material, then one targeted public pass for the remaining gaps.
Stop when the recording/artist are matched and there is enough visual evidence to
preserve or propose a world. A deliberate abstract or typographic world is valid
when likeness references are unavailable. Do not invent the artist's face.

For a blocked Instagram page, record the gap and use another accessible official
source or a supplied screenshot. Do not bypass access restrictions or claim the
page was reviewed. Do not spend beyond the existing research/concept allowance;
when none is approved, use available reads and explicitly proposed creative choices.

## 4. Keep a private source collection

Retain only useful material in the selected workspace or host-supported private
storage. Keep originals, references and generated proposals distinct. For each
retained item record:

- Stable ID, title, artist/recording association and intended use.
- Origin URL, selected local location or returned private storage key; retrieved
  time and any available source version/hash. Never invent a version.
- Whether the bytes/text were inspected, unavailable or blocked, and what was learned.
- Source kind: Recoup, customer, public or generated.
- Role: reference-only inspiration or selected production input; public visibility
  alone does not establish permission to reproduce a photograph.

Where files are supported, keep this manifest alongside the pack brief. Otherwise
retain the same small collection in the conversation and saved pack. Do not claim
all source bytes were copied when the host only supplied a URL. Preserve missing
access and expiry information so a resumed job does not rely on a vanished link.

Use `upload_release_pack_asset` only for selected supported audio/image media and
only with the discovered schema. Its returned private URL/key is the usable bridge
to production; a local path is not a backend URL. Do not send PDFs, folders or a
webpage URL as image bytes. Distill inspected text into attributed brief evidence.

Map eligible HTTPS references into `creative_context.references` when exposed.
The manifest's retrieval/version/access details remain private working context;
do not invent extra API fields. Select only production image IDs in the chosen
direction, within the exposed image limit. Preserve original attribution when a
file is copied privately. Refresh expired private URLs using supported operations,
then update/requote the same pack as required.

## Ready for creative direction

Finish discovery with matched artist/recording, occasion, established/rough/absent
direction, inspected references or an explicit creative fallback, constraints,
working mode and known spending authorization. Ask only genuinely unresolved
inputs. A brief private coverage note is enough; do not present a research report
or a list of internal fields to the customer before getting to the creative work.
